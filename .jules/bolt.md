## 2024-05-15 - Grievances feed pagination performance bottleneck
**Learning:** The grievances API feed uses cursor-based pagination sorting by `created_at` descending. Without an index on `created_at`, the database performs an O(N log N) full table sort for every feed load, which is a massive bottleneck. Adding an index fixes this. However, adding an index exposes flaky tests because bulk inserts create identical timestamps, falling back to UUID sorting which is non-deterministic.
**Action:** Always add indexes to columns used in pagination `ORDER BY` clauses, and ensure test fixtures generate unique deterministic timestamps (e.g., using `base_time - timedelta(seconds=i)`) when testing ordered queries.
